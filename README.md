## Clean Code Lessons

Some of the most valuable lessons I have learned about writing clean code in this subject:

- **Single Responsibility Principle (SRP):** Every function should do one thing only.
  Functions that get user input should not also process or print results.
- **Meaningful naming:** Variables, functions, and constants should have clear, descriptive
  names that communicate their purpose without needing a comment to explain them.
- **No global variables:** Passing data through parameters and return values makes functions
  reusable, testable, and easier to understand than relying on global state.
- **Iterative development and version control:** Committing small, working milestones with
  meaningful commit messages makes it easy to track progress and recover from mistakes.
- **DRY (Don't Repeat Yourself):** If the same logic appears more than once, it belongs in
  a reusable function — duplication leads to bugs and harder maintenance.
